# Mobile status dashboard

Open the Cloudflare Worker origin at `/mobile` from an iPhone or Android browser. The static page is public but contains no operational data. To load the dashboard, enter the existing `ENGINE_API_TOKEN`; it is held only in page memory and is not written to local/session storage, cookies, URLs, or logs. Disconnect or close the page to clear it.

The page calls the authenticated, read-only `GET /v1/mobile/status` endpoint. It reports task-state counts, append-only paper-event counts, latest paper event, latest captured market snapshot, D1 provider request/token totals, recorded model inference costs from the base `model_usage` ledger (total and provider breakdown), and recent public GitHub Actions workflow state. Model costs are recorded costs only; unreported or external spend is not inferred. It does not expose mutation controls. The endpoint checks the D1 schema migration ledger and omits paper/provider metrics cleanly when their additive migrations have not yet been applied. It also reports whether migration `0005_telegram_webhook_receipts` is present. This is a schema-readiness signal only: it does not inspect or reveal Telegram secrets, prove that the webhook is configured, or register the webhook with Telegram. The scheduled Task Runner emits only the corresponding sanitized `available`, `not_available`, or `unknown` flag in its issue status comment; it does not expose the receipt table contents or webhook credentials.

The merged Worker code adds a dashboard panel for the latest Cloudflare Worker Cron heartbeat from the existing D1 audit ledger, including the schedule and stale-lease recovery counts. The authenticated status response also includes `task_runner_watchdog`: a boolean readiness flag, names of missing GitHub App settings, the last sanitized dispatch-request metadata, and the last durable dispatch-intent timestamp. The page displays these fields without exposing any secret values. A ready configuration is not proof of a successful GitHub API dispatch; verify a real `workflow_dispatch` Task Runner run and its bounded batch result before declaring the fallback operational. The following are intentionally shown as unavailable rather than guessed: scan-run heartbeat, market-source freshness, and the engine kill-switch state (not mirrored into D1). The latest captured market snapshot is shown separately and is not presented as a scan completion or source-freshness guarantee. These require explicit, separately verified ingestion contracts before they can be displayed as current facts.

Security headers include no-store, no-referrer, nosniff, and a restrictive Content Security Policy. The page makes one unauthenticated read-only request to the public GitHub Actions API per dashboard load to show recent CI state; it does not send the Engine token to GitHub. GitHub API rate limits may make this panel temporarily unavailable. The page stores no access token persistently.

This is an additive mobile view only. It does not deploy the Worker, change secrets, apply D1 migrations, or enable external actions.
