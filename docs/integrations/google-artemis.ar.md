# تكامل Google ARTEMIS مع Raawaa Autonomous Engine

## القرار والحالة

سُجّل ARTEMIS الرسمي من `google/artemis` كتكامل اختياري لأتمتة واختبار Android. الترخيص المعلن في المستودع Apache-2.0. التكامل في Raawaa **مسجّل لكنه غير مفعّل تشغيليًا** حتى تثبت بيئة المضيف والجهاز والاتصال والميزانية.

- الحالة: `IMPLEMENTED_NOT_VERIFIED` للتسجيل ومسبار الاتصال المحلي.
- الحالة التشغيلية: `BLOCKED`؛ لم يُثبت وجود ARTEMIS daemon أو جهاز ADB مصرح به.
- إنفاق جديد: صفر. لا تثبيت أو نشر أو استدعاء نموذج من هذا المستودع.
- لا يُنسخ كود ARTEMIS إلى هذا المستودع؛ نستخدم حد HTTP ضيقًا لتجنب إدخال سلسلة تبعياته الثقيلة إلى محرك Python الحالي.

## ما الذي يضيفه؟

1. اختبار واجهات Android وواجهات الويب على متصفح Android.
2. إعادة إنتاج الأعطال وجمع trace/screenshot/logcat.
3. فحص مسارات الاستخدام متعددة الخطوات بعد تغيير واجهة.
4. تقارير QA يمكن إرجاعها إلى مهام Raawaa.

ARTEMIS ليس بديلًا عن محرك الوكلاء أو مخزن المهام أو موجّه النماذج. كما أنه ليس خدمة Gemini مجانية بحد ذاته؛ إعداداته قد تستخدم مزودات ونماذج خارجية. لذلك لا يُسمح بأي استدعاء نموذج حتى يثبت مسار مؤهل مجانيًا أو يوافق المالك على التكلفة ضمن الحدود القائمة.

## حد التشغيل الآمن الحالي

أُضيف `engine.artemis_gateway` ومهمة CLI باسم:

```bash
python -m engine.cli artemis-status
```

المسبار:
- لا ينفذ إلا طلبات GET إلى `/api/status` و`/api/devices`.
- لا يرسل مهمة إلى الهاتف ولا ينقر أو يكتب أو يثبت تطبيقات.
- يحد حجم الاستجابة إلى 256 KiB ويمنع اتباع التحويلات.
- يقبل HTTP على loopback فقط. الاتصال البعيد يتطلب HTTPS، رمزًا لمصادقة reverse proxy، وتأكيدًا صريحًا بأن المصادقة اختُبرت.
- لا يعرض محتوى الاستجابة الخام أو أسرارًا.
- إذا لم يُضبط `ARTEMIS_BASE_URL`، لا ينفذ أي اتصال شبكي.

## المتطلبات قبل التفعيل

1. مضيف مستقل مدعوم يشغل Python 3.12+ وARTEMIS وأدوات ADB المطلوبة.
2. جهاز Android أو محاكي متصل ومصرح به عبر ADB.
3. اتصال آمن من Raawaa إلى مضيف ARTEMIS. لا تعرض واجهة الإدارة غير المصادق عليها للإنترنت؛ وثائق ARTEMIS تنصح بنفق SSH أو VPN أو reverse proxy يفرض HTTPS وBearer auth.
4. اختيار جهاز محدد إذا ظهر أكثر من جهاز.
5. مراجعة تكلفة نموذج ARTEMIS وتحديد مسار مجاني مثبت. إعدادات ARTEMIS الافتراضية لا تُعد إثباتًا بأن Gemini مجاني أو أن حد الإنفاق مطبق.
6. موافقة منفصلة قبل تمكين `POST /api/run` أو أي تفاعل يغيّر حالة الجهاز.

## أين يعمل؟

ARTEMIS برنامج مضيف، وليس تطبيق Android عاديًا. يحتاج Python 3.12+ وADB وبيئة تشغيل مضيفة. وجود جهاز Android 15 وحده لا يثبت أن الجهاز قادر على استضافة كامل ARTEMIS. لا نفترض أن Cloudflare Worker يصلح لتشغيله؛ Worker لا يوفر ADB أو اتصال USB بالجهاز.

## متغيرات البيئة

تُضبط على مضيف Raawaa الموثوق أو في بيئة التشغيل، ولا تُكتب في Git:

- `ARTEMIS_BASE_URL`: عنوان خدمة ARTEMIS.
- `ARTEMIS_TOKEN`: رمز reverse proxy، وليس مفتاح Gemini.
- `ARTEMIS_REMOTE_AUTH_VERIFIED=true`: إقرار تشغيلي بأن HTTPS وBearer auth اختُبرا على reverse proxy. لا تضبطه لمجرد وجود عنوان HTTPS.

للمضيف المحلي يمكن استخدام `http://127.0.0.1:8000` دون كشفه خارج loopback.

## خطة التفعيل المرحلية

- المرحلة A — مكتملة في الكود: سجل التكامل، تسجيل دور mobile_tester معطّل، مسبار GET، اختبارات وهمية.
- المرحلة B — محجوبة: إعداد مضيف ARTEMIS وتوصيل جهاز Android بطريقة آمنة، ثم تشغيل `artemis-status`.
- المرحلة C — بعد تحقق المرحلة B: اختبار قراءة/استكشاف غير تدميري على تطبيق/صفحة يحددها المالك.
- المرحلة D — لاحقًا وبموافقة منفصلة: فتح مهمة تشغيل محددة عبر `POST /api/run`، مع موافقة لكل مهمة، وميزانية مستقلة، وقائمة تطبيقات/أفعال مسموحة، ومراجعة trace.
