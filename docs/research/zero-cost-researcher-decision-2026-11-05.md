## Minimal architecture and first engineering increment

Use existing D1 task and invocation/monetary ledgers, existing gateway and runner; make the researcher a constrained role for one public research brief, not arbitrary shell or an independent orchestration framework. No reviewer model initially. Model output is an untrusted draft; deterministic checks require nonempty bounded output, provenance and citation validation, and cannot guarantee factual correctness. Consider a separate read-only reviewer only after a blinded, fixed-fixture evaluation reports measurable error/quality improvement and bounded incremental cost.

**Next PR: offline-only targeted-claim and no-fallback contract, default disabled.** Define an explicit pilot task identity plus immutable payload digest/idempotency key. Design a single atomic D1 operation for eligibility/reservation/enqueue and a claim-by-ID fenced by a lease; concurrent producers/consumers must not cause a pilot runner to claim an unrelated task. A read of idle counts plus a later enqueue is not atomic. Confirm actual D1 transactional semantics and compatibility first; do not add schema or ship a production migration without a demonstrated need. The worker must neither claim generic pending work nor call any provider when a pilot gate, identity, current evidence, or credential is missing. Expose one allowlisted provider/model/endpoint; no Gemini credentials, tool use, service-tier fallback, other route, or provider rotation. Preserve the original evidence timestamp and source, reject stale/malformed or merely asserted billing state, and perform secret-presence checks before any enqueue (never log/hash secrets).

**Acceptance:** deterministic fake provider and local SQLite/D1 harness only. Test concurrent admissions from separate clients with one created identity; concurrent claims with one lease winner; unrelated tasks remain unchanged; replay and same-key/different-payload conflicts; missing/empty key, invalid/stale evidence and no verified cost stop cause no enqueue/claim/provider I/O; provider allowlist and zero fallback for all response classes. A successful fake result persists task/lease IDs, model/version, input digest/classification, source metadata, invocation ID, bounded output, timestamps, usage, outcome, and provenance. Capture unknown cost as **unknown**, not $0; reconcile provider billing separately before making a cost claim. Never retry after an ambiguous dispatch, lost response, crash or settlement uncertainty without provider-supported idempotency or reliable reconciliation; a stable local request ID alone cannot guarantee exactly-once external inference. Fenced stale writers must never finalize. Verify timeout, cancellation, lease expiry, crash/restart, duplicate execution, output bounds and rollback. Local concurrent tests must be labeled local; remote staging requires its own evidence and approval under the active operational boundary.

**Rollback:** keep the existing one-shot opt-in disabled; revert the reviewed code without rolling back durable records or reopening ambiguous requests. Any test deployment must use isolated staging, no production secrets or queues, and separate account/cost preflight. Until real account and end-to-end evidence exist, report `blocked`, not a successful dry-run specialist.
